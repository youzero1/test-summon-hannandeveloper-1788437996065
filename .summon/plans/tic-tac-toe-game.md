# Overview

A single-page tic-tac-toe game where the human player (X) plays against a simple computer opponent (O). The winning three-in-a-row is highlighted when the game ends. Visual direction: playful and colorful — rounded shapes, soft gradient background, bright accent colors for X and O, bouncy hover/press feedback.

---

## 1. Project scaffolding and configuration

1. Create `package.json` with the app name, ESM module type, and npm scripts for dev, build, and preview. Dependencies: react, react-dom, @tanstack/react-router. Dev dependencies: vite, @vitejs/plugin-react, typescript, @types/react, @types/react-dom, tailwindcss, @tailwindcss/vite, @tanstack/router-plugin.
   - Outcome: dependencies are declared and `npm run dev` is the entry point for local work.
2. Create `vite.config.ts` registering the React plugin, the Tailwind CSS Vite plugin, and the TanStack Router plugin (file-based routing mode pointed at `src/routes`), plus a path alias mapping `@/` to `src/`.
   - Outcome: routes are generated automatically, Tailwind processes styles, and `@/` imports resolve.
3. Create `tsconfig.json` (and `tsconfig.node.json` if needed for the Vite config) with strict mode enabled, bundler-style module resolution, JSX set for React, and the `@/*` path alias mapped to `src/*`.
   - Outcome: TypeScript compiles cleanly with strict typing and alias support.
4. Create `index.html` at the project root with a root mount element, the page title "Tic-Tac-Toe", and a script tag pointing at `src/main.tsx`.
   - Outcome: Vite has an HTML entry point that mounts the app.
5. Create `.gitignore` covering `node_modules`, `dist`, and local env files.
   - Outcome: build output and dependencies are not committed.

## 2. Styles and app entry

6. Create `src/styles/global.css` containing exactly the Tailwind import on the first line, followed only by a small set of custom utility/animation definitions used by the game (a pop-in animation for placed marks and a pulse for the winning line).
   - Outcome: Tailwind utilities are available app-wide plus two reusable playful animations.
7. Create `src/main.tsx` to import the global stylesheet once, create the TanStack Router instance from the generated route tree, and render the router into the root element inside React's strict mode.
   - Outcome: the app boots and routing is active.
8. Note that `src/routeTree.gen.ts` is generated by the router plugin on first dev/build run — it must never be hand-written or edited.
   - Outcome: no manual route registry to maintain.

## 3. Route shell

9. Create `src/routes/__root.tsx` as the app shell: a full-height page with a soft multi-color gradient background, centered content container, and an outlet for the active route.
   - Outcome: every screen inherits the colorful backdrop and centered layout.
10. Create `src/routes/index.tsx` as the home route that renders the game screen component and nothing else of substance.
    - Outcome: visiting the site root shows the game immediately, with no navigation needed.

## 4. Game types and logic

11. Create `src/types/game.ts` defining shared types: a cell value (X, O, or empty), the board as a fixed-length collection of nine cells, the player identity, and a game-status shape that covers in-progress, win (with the winning cell positions), and draw.
    - Outcome: one source of truth for game data shapes across components and hooks.
12. Create `src/lib/gameLogic.ts` with pure helper functions: create an empty board; return all eight winning line position triples; evaluate a board to produce a status (winner plus winning positions, draw, or ongoing); list currently empty cell positions.
    - Outcome: win/draw detection and the winning-line positions are computed in one testable place, independent of UI.
13. Create `src/lib/computerPlayer.ts` with the simple AI move chooser, ordered by priority: take an immediate winning move, otherwise block the human's immediate winning move, otherwise take the center, otherwise take a random free corner, otherwise take any random free cell.
    - Outcome: the computer feels competent but beatable — appropriate for a casual game.

## 5. Game state hook

14. Create `src/hooks/useTicTacToe.ts` holding all game state: the board, whose turn it is, the derived status, a flag for when the computer is "thinking", and a round counter used to re-trigger animations on reset.
    - Outcome: the UI stays presentational while all rules live in one hook.
15. In the same hook, expose an action for the human playing a cell that ignores clicks on filled cells, on a finished game, or while the computer is moving.
    - Outcome: no illegal or double moves are possible.
16. In the same hook, add an effect that, when it becomes the computer's turn and the game is unfinished, waits a short delay (roughly half a second) and then applies the chosen computer move — cleaning up the timer if the component unmounts or the game resets mid-delay.
    - Outcome: the computer's move feels deliberate rather than instant, with no stray moves after a reset.
17. In the same hook, expose a reset action that clears the board, returns the turn to the human, and increments the round counter.
    - Outcome: "Play again" fully restarts the round.

## 6. UI components

18. Create `src/components/GameBoard.tsx` rendering a responsive three-by-three grid of cells with a thick rounded frame, receiving the board, the winning positions, a disabled state, and a cell-click callback.
    - Outcome: the playing surface, driven entirely by props.
19. Create `src/components/Cell.tsx` as an accessible button for a single square: large rounded tile, distinct bright color for X versus O, pop-in animation when a mark appears, hover/press feedback only when the cell is playable, and a highlighted (glowing, pulsing) treatment when the cell is part of the winning line.
    - Outcome: each square reads clearly and the winning three-in-a-row visibly stands out.
20. Create `src/components/StatusBanner.tsx` showing the current state in friendly wording: "Your turn", "Computer is thinking…", "You win!", "Computer wins", or "It's a draw" — with color and emoji shifting to match the outcome.
    - Outcome: the player always knows what is happening and how the round ended.
21. Create `src/components/GameScreen.tsx` composing the whole experience: playful title, the status banner, the board, and a prominent "Play again" button that is emphasized once the round is over.
    - Outcome: a single component the home route can render, with the full game assembled.

## 7. Polish and verification

22. Ensure keyboard and screen-reader support across `src/components/Cell.tsx` and `src/components/StatusBanner.tsx`: squares are focusable buttons with descriptive labels, filled or disabled squares are properly marked unavailable, and status changes are announced politely.
    - Outcome: the game is playable without a mouse.
23. Confirm the layout at small screen widths in `src/components/GameScreen.tsx` and `src/components/GameBoard.tsx` — the board should stay square and fully visible on a phone without scrolling.
    - Outcome: comfortable play on mobile and desktop.
24. Manually verify all outcomes: a human win highlights the correct line, a computer win highlights its line, a full board with no winner reports a draw, clicks are ignored after the game ends, and "Play again" restores a clean empty board with the human to move.
    - Outcome: the game is complete and behaves correctly in every end state.
